# Security policy

This project is pre-release and exposes local-drive capacity measurement, explicit folder metadata scans, an approved common-location scan, bounded duplicate analysis, conservative review classification, individually confirmed quarantine, and safe restore in the native app. Capacity measurement does not traverse a drive. Duplicate analysis groups by size before locally streaming SHA-256 for same-size candidates; content and hashes are not uploaded or persisted, and the report cannot authorize a file operation. User exclusions must be relative to a scan root and are independently validated by Rust before traversal. Quarantine accepts only opaque identifiers from the latest completed cleanup scan, revalidates the source against its originating root, journals intent locally, and Restore refuses to overwrite an existing item. Permanent deletion is unavailable. No version is supported for production cleanup.

Do not post private filenames, file contents, credentials, or exploitable details outside the private repository. GitHub dependency vulnerability alerts and automated security fixes are enabled. Before any public release, maintainers must also configure a monitored private reporting channel and document its response process.

Reports should include the affected revision, platform, impact, and a reproduction using synthetic files. Avoid attaching real user data. Response-time guarantees cannot be made before maintainers and a reporting channel are established.
